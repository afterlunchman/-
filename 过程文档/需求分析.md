## 二、项目背景与定位

同学在宿舍、实验室、实习、消防、传染病防控等场景中经常需要确认「能不能做」「多久内上报」「按什么流程办」，但制度分散在 155 份文件、106 个 PDF 附件中，人工检索成本高，且扫描件存在 OCR 噪声。

本项目做一个**有据可查的问答助手**：用户用自然语言提问，系统检索制度原文，给出**带条号与来源链接的答案**；证据不足时**明确拒答**，而不是编造。项目的核心不是「接一个大模型」，而是用课程方法把**检索、生成、校验、评估**串成可复现的流水线。

**成功的样子**：一个同学问「宿舍能用大功率电器吗」，系统在 3 秒内返回「不得使用」的结论、对应条款原文、制度名称与官网链接；问「补考成绩怎么算」时，系统回答「现有语料未覆盖学籍考试制度，建议咨询教务处」，而不是编一个答案。

## 三、用户与使用场景

### 3.1 目标用户

- **在校本科生 / 研究生**：查询宿舍、实验室、消防、实习、传染病防控等安全规定。
- **辅导员 / 班委**：快速定位制度依据，用于班会与日常管理。
- **安全管理人员**：核对某条规定的原文、条号与发布信息。

### 3.2 典型问题类型

| 类型 | 示例 | 主要考察能力 |
| --- | --- | --- |
| 定义 / 禁止性 | 宿舍里可以使用大功率电器吗？ | 单条款定位 |
| 数值 / 期限 | 实验室事故应在多长时间内上报？ | 精确数值抽取 |
| 流程 / 职责 | 发生火灾后先做什么、向谁报告？ | 多条款组合 |
| 跨文档 | 本科生进实验室需要哪些培训和审批？ | 多文档检索 |
| 边界 / 否定 | 可以让外校同学留宿吗？ | 条件与例外识别 |
| 不可答 | 补考成绩怎么算？ | 拒答，不编造 |

### 3.3 不在范围内

- 学籍、考试、奖惩、评奖评优、选课、收费等非安全类制度（本期语料不覆盖）。
- 实时办事流程、表单下载、审批进度查询。
- 法律意见、个案裁决与责任认定。
- 多轮追问与个性化推荐（本期只做单轮问答）。

## 四、语料分析

### 4.1 规模与结构

- 155 份制度，5 大板块、38 个栏目节点，正文合计 **1,337,704 字**。
- 106 个附件 PDF（137 MB），`index.jsonl` 每行一条，含 `doc_id`、`title`、`section`、`source_url`、`text_source`、`attachments` 等字段。
- 正文来源：`web_page` 63 条、`pdf_text_layer` 63 条、OCR 29 条（视觉模型 13、RapidOCR 13、混合 3）。
- 全部条目 `ocr_needed=false`，可直接入库。
- 正文按「第 X 条」组织，天然适合**条文级切块**。

### 4.2 质量风险与设计约束

| 风险 | 具体表现 | 设计约束 |
| --- | --- | --- |
| OCR 噪声 | 字符混淆（`一`↔`-`、`；`↔`：`）、表格被展平 | chunk 携带 `confidence`；低置信内容降权；数值/期限题提示核对原件 |
| 时效性 | `published_at` 是页面发布时间，不等于现行有效版本 | 回答统一注明「以官网最新版本为准」，附原文页链接 |
| 标题失真 | 部分栏目标题是分类名而非制度名 | 以正文首行标题二次识别，保留栏目路径 |
| 快照限制 | 单次抓取（2026-10-24），源站修订不同步 | README 说明快照日期；不做「最新版」承诺 |
| 附件依赖 | 关键数值可能在 PDF 原件中 | 每个 chunk 保留 `attachment_url`，答案可跳转核对 |

## 五、功能需求

### F1 语料解析与切块

- 读取 `index.jsonl` 与对应 Markdown，解析 frontmatter。
- 按 `第[一二三四五六七八九十百零\d]+条` 做**条文级切块**：一个 chunk = 一条；OCR 文本将 `【第 n 页】` 转为 `page` 元数据。
- 无条号的制度（通知、办法类）回退为 400—600 字、按段落边界切分，`clause_no=null`，并在元数据中标记 `chunk_kind=paragraph`。
- **父级扩展**：检索命中后，上下文 = 制度标题 + 命中条 + 前后各一条 + 页码 + 来源链接；扩展窗口可配置（0 / ±1 / ±2 条）。
- 每个 chunk 至少包含：`chunk_id`、`doc_id`、`title`、`section`、`clause_no`、`chunk_kind`、`page`、`text`、`text_source`、`confidence`、`source_url`、`attachment_url`。
- **验收**：155 份全部入库；输出 chunk 总数、平均长度、条号覆盖率、无条号条目清单、各栏目分布；索引可由脚本重建。

### F2 多路检索

- BM25（jieba 分词）、词向量平均（Word2Vec 在语料上训练）、BGE dense（`bge-small-zh-v1.5`，numpy 持久化）。
- Hybrid：BM25 + dense 用 RRF 融合；可选 rerank（BGE-reranker / API）。
- `top_k`、`chunk_size`、融合方式可配置；返回分数与完整元数据。
- **验收**：单查询检索耗时（模型加载后）< 1s；可计算 Recall@1/3/5 与 MRR@10。

### F3 答案生成（强制引用）

- 仅使用检索到的上下文回答，不引入外部知识。
- 每个事实性陈述附 `[制度名 第X条]`；答案末尾列出来源链接。
- 证据不足时输出拒答，并说明缺什么。
- 输出结构化 JSON：`answer`、`citations`、`refused`、`confidence`、`used_chunk_ids`。
- **验收**：JSON 解析成功率 100%；随机抽 20 条人工检查格式与引用风格。

### F4 引用校验

- **一级：规则校验（全量，零 API 成本）**
  - 答案引用的条号必须出现在本次检索上下文中；
  - 引用原文能与对应 chunk 文本对齐（允许空白与标点归一化）；
  - 校验失败直接标记，不进入答案。
- **二级：LLM 支持度校验（条件触发）**
  - 仅当答案含数值、期限、罚则、禁止性结论时触发，调用独立评审模型判断「被引条款是否支持该陈述」；
  - 不通过 → 重新生成一次 → 仍不通过则降级为「未找到明确依据」或拒答。
- 记录校验通过率、触发比例、拦截案例与失败原因。
- **验收**：可统计「引用支持率」与「校验拦截率」，并在 Web 界面标注低置信引用。

### F5 拒答

两类触发：检索最高分低于阈值；上下文不含答案或答案冲突。
- 不可答集：正确拒答并给出建议咨询部门。
- 可答集：误拒率需受控。
- **验收**：10 道不可答题拒答率 ≥ 80%；70 道可答题误拒率 ≤ 10%。

### F6 Web 界面（Streamlit）

- 输入框、示例问题、答案区、引用卡片（制度名 / 条号 / 页码 / 来源链接 / 置信度）。
- 可展开的检索 Top-k 列表与分数，便于演示「为什么这样答」。
- 显示耗时与本次 token 成本。
- 低置信或 OCR 来源时给出显著提示。
- **验收**：`streamlit run` 本地可跑通；2 分钟录屏可完整展示正常问答 + 一个难例。

### F7 评估与日志

- 批量脚本读取 `data/eval/questions.jsonl`，对 B0—B5 各跑一遍，输出逐题结果与汇总指标。
- 日志记录：query、检索结果 ID 与分数、prompt/completion tokens、延迟、模型名、时间戳。
- **验收**：一条命令复现报告主表；报告中的数字可在 `results/` 与 `logs/` 中找到出处。

## 九、评测集设计

- **规模**：80 题 = 70 可答 + 10 不可答。
- **可答题分布**（按板块配额）：综合法律法规 15、专项法律法规 20、综合安全制度 10、专项安全制度 20、应急预案 5。
- **题型分布**：定义/禁止 20、数值/期限 15、流程/职责 15、跨文档 10、边界/否定 10。
- **不可答题**：语料外主题 5 题（学籍、考试、收费等）+ 语料内无明确答案 5 题。
- **字段**：`question_id`、`question`、`type`、`answerable`、`gold_doc_ids`、`gold_clauses`、`gold_answer`、`evidence_span`、`difficulty`、`annotator`、`reviewer`。
- **流程**：AI 基于条文起草 → 4 人各负责 20 题改写与校验 → 交叉复核 → 争议合议。
- **评审模型**：与生成模型不同，单独配置 `evaluation.judge_model`；若只有单一可用模型，报告中明确 self-preference 偏差。
- **抽检**：LLM judge 评全部 80 题；人工抽检 24 题（30%），报告一致率与 Kappa，目标 ≥ 0.8。

## 十一、三个原理点与实验证据

1. **第 5 讲：词向量与句向量的表示能力差异**
   - 证据：B2 与 B3 的 Recall@k 对比；词袋平均丢失语序与否定（如「不得留宿」与「可以留宿」向量几乎相同）的具体样例；OOV 与近义词案例。
2. **第 15 讲：召回是上限、重排与引用校验的作用**
   - 证据：检索 Recall 与端到端正确率的分组关系；rerank 前后指标与延迟对比；引用校验拦截的幻觉案例统计。
3. **第 14 讲：评测指标与评测协议的选择依据**
   - 证据：为何用 Recall@k + rubric + 拒答率而非单一 EM/F1；judge-human 一致率；不可答集的设计依据与结果。

## 十二、系统架构与数据流

```
用户问题
   │
   ├─ 查询处理（归一化 / 可选同义扩展）
   │
   ├─ 并行检索
   │    ├─ BM25（jieba）
   │    ├─ 词向量平均（Word2Vec）
   │    └─ BGE dense（bge-small-zh-v1.5）
   │
   ├─ RRF 融合 → 可选 rerank（top_n）
   │
   ├─ 上下文组装（命中条 + 前后各一条 + 制度名 + 页码 + 置信度 + 来源链接）
   │
   ├─ LLM 生成（强制引用；证据不足则拒答）
   │
   ├─ 引用校验（条号存在性 + 支持度）
   │       └─ 不通过 → 重生成 / 降级 / 拒答
   │
   └─ 输出（答案 + 引用卡片 + 原文链接 + 置信度 + 耗时/成本）
```

数据层：`index.jsonl` + Markdown → 解析 → 条文级 chunk → BM25 索引 / numpy 向量索引。

## 十五、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| API 不稳定或限流 | 评测中断 | 重试 + 结果缓存（同 query 落盘）；准备备用 provider |
| BGE 模型下载慢 / CPU 推理慢 | 建库延迟 | 默认 `bge-small-zh-v1.5`；有 GPU 用 CUDA；`bge-m3` 作为升级项 |
| OCR 噪声导致数值错误 | 答案错误 | chunk 置信度降权；数值题提示核对原件；错误分析单列一类 |
| 标注时间超支 | 评测集缩水 | 先 40 题跑通，再扩到 80；AI 初稿 + 人工校验 |
| 工期仅 6 天 | 报告仓促 | 实验脚本化、结果自动出表；报告边跑边写 |
| 不可答被误答 | 幻觉 | 检索阈值 + 提示拒答 + 引用校验三重防护 |
| 扫描件引用不可核 | 用户不信任 | 引用卡片直接给 PDF 附件链接与页码 |
| 无条号制度 | 条文切分失败 | 回退段落切分，`clause_no=null`；统计无条号条目占比并写入报告 |
| 只有单一可用模型 | 评审自偏好 | 报告中明确偏差；用 24 题人工抽检校准评审结论 |
